# The source-distillation thread

Turn one blog post or repo story into a standalone-useful X thread. This is the only template.

## Steps

1. Read the source in full. Extract the event (what happened), the numbers (exact, with units, as the source states them), the technique or lesson, and what the author verified live versus what he did not.
2. Post 1 stands alone: the event, the number, the point. It works as a single tweet if the rest never gets read.
3. Middle posts: one idea per post, in plain sentences. Say what happened, then what it meant. Never a teaser for the next post. No numbered headings unless the posts are actual sequential steps.
4. Last post: the takeaway in one or two sentences. Not a CTA, not a link dump. Then the source URL on its own line.
5. Three to five posts. If it needs more, it is a blog post and the thread is its summary.

## Voice and shape

Per ~/workspace/skills/wes-voice/SKILL.md, mandatory. First line is the concrete thing that happened, with the real number. Show the thing working before stating any philosophy about it. Understated excitement, short sentences, first person. The tool gets named in the sentence where it did something, not before.

Never: engagement bait ("who else", "what are you building", "where is your line"), rhetorical questions as closers, motivational sign-offs, arrow bullets, cliffhanger line breaks, or a fabricated event to make the hook land. If the real story is smaller than the hook wants, shrink the hook.

## Checks before committing

- Every number appears in the source. When unsure, grep the source.
- Could anyone else have posted this? If yes, it dies.
- No em dashes.
